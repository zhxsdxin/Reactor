二、深度拆解：sock_handler.cpp（手把手教学）

这是整个项目里最典型的一个文件——有读、有写、用到了线程池、处理了断开连接。
我们逐段拆解，理解每一行是干什么的、为什么这么写。

2.1 先看头文件（定结构）

include/sock_handler.h — 声明了类有哪些成员：

 1#pragma once
 2#include "event_handler.h"
 3#include <string>
 4#include <vector>
 5#include <mutex>

 7class SockHandler : public EventHandler,
 8                     public std::enable_shared_from_this<SockHandler> {
 9public:
10    explicit SockHandler(Handle fd);   // 构造函数：传入客户端 fd
11    ~SockHandler() override;
12    Handle get_handle() const override { return sock_fd_; }
13    void handle_read() override;
14    void handle_write() override;
15    void handle_error() override;
16    void handle_close() override;

19private:
20    Handle sock_fd_ = INVALID_HANDLE;
21    static const size_t BUFFER_SIZE = 1024;

逐行解释：

第 7-8 行 双重继承：
EventHandler — 必须实现的接口：handle_read / write / error / close
enable_shared_from_this — 让类内部能用 shared_from_this() 获取自己的 shared_ptr。为什么要这个？因为 handle_read 里要把数据"丢给线程池"，线程池的 lambda 需要持有 SockHandler 的指针防止被销毁。
第 20 行sock_fd_ — 客户端的 socket 文件描述符。就是一个 int 数字（比如 7），代表这个 TCP 连接。
第 21-22 行PDF 要求的 1024 字节缓冲区。read_buffer_ 是一个 char 数组，每次 read 最多读 1024 字节。注意这是固定大小（栈上分配），不是 new 出来的——符合"少量 new"的要求。
第 23 行write_buffer_ — 写缓冲区。是一个 vector<char>，可以动态扩容。为什么要写缓冲区？因为 write 不一定一次写完（网络拥堵时返回 EAGAIN），剩余数据要暂存起来等下次发。
第 24 行write_mutex_ — 互斥锁。因为线程池 worker 也会往 write_buffer_ 里写数据，所以需要锁保护。

2.2 构造函数和析构函数（第 10-21 行）

10SockHandler::SockHandler(Handle fd)
11    : sock_fd_(fd)          // 初始化列表：把传入的 fd 存下来
12{
13    memset(read_buffer_, 0, BUFFER_SIZE);  // 读缓冲区清零
14}
15
16SockHandler::~SockHandler()
17{
18    if (sock_fd_ != INVALID_HANDLE) {  // 如果还没被 close 过
19        close(sock_fd_);                 // 关闭 socket
20    }
21}
第 10-11 行初始化列表是 C++ 最推荐的初始化方式。括号里直接写 fd，不需要在函数体里赋值。
第 13 行memset 把整个数组填成 0，防止读到上一次的脏数据。
第 18 行防御式编程：检查 fd 是否还有效。如果 handle_close 已经被调用过，sock_fd_ 就是 -1（INVALID_HANDLE），不再重复 close。

2.3 set_nonblocking（第 23-28 行）

23void SockHandler::set_nonblocking()
24{
25    if (sock_fd_ == INVALID_HANDLE) return;   // 无效就不操作
26    int flags = fcntl(sock_fd_, F_GETFL, 0);  // ① 获取当前标志位
27    fcntl(sock_fd_, F_SETFL, flags | O_NONBLOCK); // ② 加上 O_NONBLOCK 再写回去
28}

为什么要非阻塞？
如果 socket 是阻塞的，read() 没有数据时会卡住整个线程，导致其他 9999 个连接全部得不到处理。非阻塞模式下，没有数据时 read 立刻返回 -1 + EAGAIN，Reactor 可以接着处理下一个连接。

2.4 handle_read — 核心！（第 30-72 行）

这是整个 Echo 服务器最核心的函数。分三层来理解：

第一层：整体结构

void SockHandler::handle_read()
{
    if (sock_fd_ == INVALID_HANDLE) return;   // 守卫：已经关了就不处理

    while (true) {                             // 循环读，直到没数据为止
        ssize_t n = read(sock_fd_, read_buffer_, BUFFER_SIZE);

        if (n > 0)           { /* 读到了 n 字节，处理 */ }
        else if (n == 0)     { /* 客户端断开了 */ }
        else /* n < 0 */   { /* 出错了或没数据了 */ }
    }
}

第二层：分支详解

分支 A：n > 0（读到了数据）— 第 37-54 行

37        if (n > 0) {
38            printf("[SockHandler] fd=%d read %zd bytes\n", sock_fd_, n);
39
40            // 拷贝数据到 string（因为 read_buffer_ 马上会被下一次 read 覆盖）
41            std::string data(read_buffer_, n);
42            auto self = shared_from_this();      // 获取自己的 shared_ptr
43            Reactor::get_instance().get_thread_pool().submit(
44                [self, data = std::move(data)]() {   // lambda 捕获 self 和 data
45                    {
46                        std::lock_guard<std::mutex> lock(self->write_mutex_);
47                        self->write_buffer_.insert(self->write_buffer_.end(),
48                                                   data.begin(), data.end());
49                    }
50                    Reactor::get_instance().modify_handler(
51                        self->get_handle(), EVENT_READABLE | EVENT_WRITABLE);
52                });
53        }

这段代码做了什么？（每行解读）

41把读到的数据拷贝到 std::string data。为什么拷贝？因为 read_buffer_ 是成员变量，下一次 read 会覆盖它。如果直接把 read_buffer_ 的地址传给线程池，线程池处理时数据已经被下一次 read 改掉了。
42shared_from_this() 获取当前对象的 shared_ptr。这是为了安全——线程池的 lambda 可能在未来某个时刻执行，必须确保那时候 SockHandler 对象还活着。shared_ptr 会增加引用计数，只要 lambda 还持有它，对象就不会被析构。
43-44向线程池投递一个任务。lambda 里捕获了 self（自己的 shared_ptr）和 data（要处理的数据）。data = std::move(data) 是把 data 移动进 lambda，不额外拷贝。
46-48线程池 worker 执行时：先加锁，然后把 data 追加到 write_buffer_ 尾部。insert 是往 vector 末尾塞数据，end() 表示末尾位置。加锁是因为 handle_write 也同时访问 write_buffer_。
50-51调用 modify_handler 告诉 Reactor："这个 fd 现在可写了，下次 epoll 可写时叫我"。参数 EVENT_READABLE | EVENT_WRITABLE 表示既关心可读（客户端可能继续发数据）又关心可写（我们已经准备好了回复）。

💡 关键理解：这就是"多线程加分项"的核心。
handleRead "只做数据读取，然后把数据交给线程池去做耗时处理"——PDF 原文。这里的"处理"是简单的 echo（啥也没变），实际项目里可以在这里做 JSON 解析、加密解密、查数据库等耗时操作，都不会阻塞 Reactor 主循环。

分支 B：n == 0（客户端断开连接）— 第 56-61 行

56        } else if (n == 0) {
57            printf("[SockHandler] fd=%d disconnected\n", sock_fd_);
58            handle_close();           // 关闭 socket
59            Reactor::get_instance().remove_handler(sock_fd_); // 从 Reactor 移除
60            return;

当客户端正常关闭连接（发 FIN），read 返回 0（EOF）。这时要做两件事：① 关闭 socket、② 告诉 Reactor "不用再盯着这个 fd 了"。

分支 C：n < 0（出错或没数据）— 第 63-69 行

63        } else {
64            if (errno == EAGAIN || errno == EWOULDBLOCK) break; // 没数据了，退出循环
65            perror("[SockHandler] read error");
66            handle_error();
67            handle_close();
68            Reactor::get_instance().remove_handler(sock_fd_);
69            return;

关键：EAGAIN 和 EWOULDBLOCK 不是真正的错误。在非阻塞 socket 上，如果内核缓冲区暂时没有数据，read 会返回 -1 并设 errno=EAGAIN。这表示"现在没数据，下次再来"——break 退出读循环就好了。如果是其他 errno（比如连接被重置），才是真正的错误，需要关闭。

第三层：为什么是 while(true)？

因为默认使用水平触发（LT）模式。LT 的意思是：只要 socket 接收缓冲区里还有数据，epoll 就会反复报"可读"。与其让 epoll 报一次读一次，不如一次读完。while + 非阻塞 read 读到 EAGAIN 为止，能大幅减少 epoll_wait 的调用次数。

2.5 handle_write — 写数据（第 74-101 行）

74void SockHandler::handle_write()
75{
76    if (sock_fd_ == INVALID_HANDLE) return;
77
78    std::lock_guard<std::mutex> lock(write_mutex_);  // 加锁保护写缓冲区
79
80    if (write_buffer_.empty()) return;  // 没数据要写，直接返回
81
82    while (!write_buffer_.empty()) {
83        ssize_t n = write(sock_fd_, write_buffer_.data(), write_buffer_.size());
84
85        if (n > 0) {
86            write_buffer_.erase(write_buffer_.begin(), write_buffer_.begin() + n);
87                                                  // 删掉已发送的 n 字节
88        } else if (n < 0 && (errno == EAGAIN || errno == EWOULDBLOCK)) {
89            // 发送缓冲区满了，告诉 Reactor 继续关心可写
90            Reactor::get_instance().modify_handler(sock_fd_,
91                            EVENT_READABLE | EVENT_WRITABLE);
92            return;   // 等下次可写继续发送
93        } else {
94            // 真正的写错误
95            perror("[SockHandler] write error");
96            handle_error(); handle_close();
97            Reactor::get_instance().remove_handler(sock_fd_); return;
98        }
99    }
100
101    // 写完了，恢复为只关心可读（否则每次循环都触发可写事件，空转浪费 CPU）
102    Reactor::get_instance().modify_handler(sock_fd_, EVENT_READABLE);
103}

关键细节：

78加锁保护 write_buffer_，因为线程池 worker 也在往里面写（见 handle_read 第 46 行）。同一时刻只能有一个线程操作 write_buffer_。
86erase(begin, begin+n) 从 vector 头部删掉已发送的 n 个字节。vector 的 erase 会把后面的元素往前移，时间复杂度 O(n)。如果追求极致性能可以用循环队列（deque），但学生项目用 vector 足够了。
88-92写不出去怎么办？write() 返回 -1 + EAGAIN，说明内核的发送缓冲区满了（对端接收太慢）。这时把数据留在 write_buffer_，注册可写事件。等 socket 可写时 epoll 会再通知我们，handle_write 被再次调用，继续发送剩余数据。
102全部发完后的收尾：恢复为只关心 EVENT_READABLE。如果不这样做，每次 epoll_wait 都会说"这个 fd 可写"，导致 handle_write 被反复调用但每次进去发现 buffer 是空的——纯浪费 CPU。这就是 Reactor 模式里"修改关心事件"的典型用法。

2.6 handle_close（第 108-115 行）

108void SockHandler::handle_close()
109{
110    if (sock_fd_ != INVALID_HANDLE) {   // 防止重复关闭
111        printf("[SockHandler] closing fd=%d\n", sock_fd_);
112        close(sock_fd_);                 // 系统调用：关闭 socket
113        sock_fd_ = INVALID_HANDLE;       // 标记为 -1，防止下次再 close
114    }
115}

为什么第 110 行要检查？因为 handle_close 可能被多次调用：比如 handle_read 里检测到断开调了一次，析构函数又会调一次。第 113 行把 sock_fd_ 设为 -1，第二次进来检查到 -1 直接跳过。

三、其余文件逐个讲解

3.1 include/event_handler.h — 所有 Handler 的"合同"

enum EventType : uint32_t {
    EVENT_READABLE  = 0x01,   // 0001 — 可读
    EVENT_WRITABLE  = 0x02,   // 0010 — 可写
    EVENT_ERROR     = 0x04,   // 0100 — 错误
};
// 位掩码的好处：EVENT_READABLE | EVENT_WRITABLE = 0x03 = "既读又写"

class EventHandler {
    virtual Handle get_handle() const = 0;  // "你的 fd 是多少？"
    virtual void handle_read() = 0;         // "可读了，去处理"
    virtual void handle_write() = 0;        // "可写了，去发送"
    virtual void handle_error() = 0;        // "出错了，去善后"
    virtual void handle_close() = 0;        // "关闭连接，清理资源"
};

每个 = 0 的函数是纯虚函数，子类必须实现。编译器会检查——漏掉任何一个子类都编译不过。这就是 C++ 的多态：Reactor 只持有 EventHandler 指针，不关心具体是 ListenHandler 还是 SockHandler，统一调这四个方法。

3.2 include/event_demultiplexer.h — 多路分解器接口

class EventDemultiplexer {
    virtual int  wait_event(vector<ReadyEvent>&, int timeout) = 0;
    virtual bool regist(Handle, uint32_t evt) = 0;
    virtual bool remove(Handle) = 0;
    virtual bool modify(Handle, uint32_t evt) = 0;
};

四个纯虚函数 = 四个"填空题"，EpollDemultiplexer 和 SelectDemultiplexer 各自用不同的系统调用填这个空。

3.3 src/epoll_demultiplexer.cpp — epoll 封装（核心必做）

构造函数里调 epoll_create1(0) — 向内核申请一个 epoll 实例，返回值存到 epoll_fd_。

regist里调 epoll_ctl(EPOLL_CTL_ADD) — 告诉内核"盯着这个 fd"。

wait_event里调 epoll_wait — 睡觉等事件。醒来后把就绪 fd 填入 ready_events vector。

"不可滥用内存分配"的要求：evs_ 数组在构造函数里一次性分配 1024 个元素，之后反复使用，不会再 new。wait_event 里的 ready_events 用 reserve 预分配，减少 push_back 时的重新分配。

3.4 src/select_demultiplexer.cpp — select 封装（加分）

用三个 fd_set（read_set_、write_set_、except_set_）维护监听列表。regist 用 FD_SET 添加，remove 用 FD_CLR 删除。wait_event 调 select()，然后从 0 到 max_fd_ 遍历找就绪的 fd。

select 和 epoll 的区别：epoll 直接告诉你"哪几个 fd 就绪了"，select 只改了 fd_set，你得自己遍历。select 还有 1024 个 fd 的上限（FD_SETSIZE）。

3.5 src/reactor_impl.cpp — 调度中心

三个管理函数：

register_handler① handlers_[fd] = handler
② demux->regist(fd, events)
remove_handler① demux->remove(fd)
② handlers_.erase(fd)
modify_handler① handler->set_events(evt)
② demux->modify(fd, evt)

核心函数 wait_and_dispatch：

int ReactorImplementation::wait_and_dispatch(int timeout_ms)
{
    vector<ReadyEvent> ready;
    demux_->wait_event(ready, timeout_ms);  // ① 等内核通知

    for (每个就绪事件) {
        handler = handlers_[fd];            // ② 查映射表
        // 注意：这里先释放锁再调回调（避免死锁）
        if (可读) handler->handle_read();    // ③ 调回调
        if (可写) handler->handle_write();
    }
}

为什么要释放锁再调回调？
因为 handle_read 里可能调 remove_handler，remove_handler 也要拿同一把锁。持锁调回调 = 死锁。

3.6 src/reactor.cpp — 单例 + 事件循环

Reactor& Reactor::get_instance() {
    static Reactor instance;       // C++11 局部静态变量：线程安全的懒汉单例
    return instance;
}

void Reactor::event_loop(int timeout) {
    while (running) {
        int t = timer->get_next_timeout_ms();  // ① 算超时（定时器 or 默认）
        impl->wait_and_dispatch(t);            // ② 等事件 + 分发
        timer->tick();                         // ③ 触发到期定时器
    }
}

3.7 src/listen_handler.cpp — Acceptor（门童）

start() 函数 = TCP 服务器五步：

socket()   →  创建一个 TCP socket, 拿到 fd
setsockopt  →  设置 SO_REUSEADDR（端口复用）
fcntl       →  设为 O_NONBLOCK（非阻塞）
bind()     →  绑定 0.0.0.0:8080
listen()   →  开始监听

handle_read 函数 = 循环 accept：

while (true) {
    client_fd = accept(listen_fd_);   // 接受新连接
    if (client_fd < 0) break;         // 没有更多了（EAGAIN）

    创建 SockHandler(client_fd)       // 为这个连接建一个服务员
    register_handler(sock, READABLE) // 注册到 Reactor
}

3.8 src/thread_pool.cpp — 线程池（加分项）

ThreadPool(4) {
    创建 4 个线程，每个跑 worker_loop()
}

worker_loop() {
    while (运行中) {
        cond.wait(锁, []{ return 有任务了 || 要停了; });  // 没活干就睡觉
        task = tasks.front(); tasks.pop();                  // 取一个任务
        lock.unlock();                                      // 释放锁
        task();                                             // 执行（不持锁）
    }
}

条件变量 + 任务队列（FIFO），是多线程编程的基础模型。

3.9 src/timer.cpp — 定时器（加分项）

用 priority_queue + greater 实现小顶堆，堆顶总是最早到期的定时器。

add_timer(5000, cb)  →  算 deadline = now + 5秒 → 推入堆
tick()               →  检查堆顶是否到期 → 到期就执行回调 + 弹出

3.10 src/main.cpp — 入口

main() {
    注册信号处理（Ctrl+C）
    创建 Reactor 单例
    创建 ListenHandler → start()
    添加定时器（每 5 秒打印状态）
    event_loop()        // 死循环，直到 Ctrl+C
}

Windows 上用 WSL 跑

项目源码用了 epoll，只能在 Linux 环境编译。Windows 下请用 WSL2（Linux 子系统），一次装好，之后都能用。
① 装 WSL（以管理员身份打开 PowerShell）： 
wsl --install
装完重启电脑，首次打开 Ubuntu 会要求设置用户名/密码。 ② 进 Ubuntu 装编译工具： 
sudo apt update
sudo apt install -y g++ netcat-openbsd
③ 直接进入项目所在目录跑演示（wsl 能访问你的 Windows 盘）： 
# 项目在 C:\Users\v_shinzhang\Downloads\Reactor
cd /mnt/c/Users/v_shinzhang/Downloads/Reactor
bash demo.sh

10 客户端并发演示

项目根目录的 demo.sh 一键执行完整演示： 
# 脚本分四步：编译 → 启动服务器 → 起 10 个客户端并发 → 停服务器
bash demo.sh

# 期望输出：每一行都是 ✓（发送=接收回显）
[✓] 客户端 #1: 发送=接收 → 正确
[✓] 客户端 #2: 发送=接收 → 正确
...（共 10 行）

也可以在脚本末尾加 sleep 3 让服务器多运行一会儿，方便你截图服务器日志。
